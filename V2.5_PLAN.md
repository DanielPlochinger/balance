# Balance v2.5 — remote truth

Status: LOCKED 2026-08-16. Awaiting Daniel's explicit go; this doc alone must suffice to build from.

## 1. Architecture: the repo is the only truth

- Every read and write goes to `balance-data/state.json`. There is no other authoritative copy, ever.
- Local storage becomes a **display cache** only: render last-known data instantly on open, then refresh from remote. The cache is never merged back into anything.
- Writes are **remote-first**: fetch fresh state → apply the single mutation → PUT with version check (sha). On conflict: refetch, reapply the same mutation, retry (max 3). The UI confirms a log only after the repo accepts it.
- Offline = **read-only**: logging disabled with a clear offline state; no write queues.
  *Intent: a second truth must never exist, not even temporarily — queues are a local truth through the side door.*

## 2. Machinery deleted

- The merge engine (`mergeState`), the content-guard, food and entry tombstones, the `wipedAt` purge system, lazy `stampDays()` and all its ordering rules. This entire bug class dies with the copies it protected.
- Migration physically removes tombstoned foods from state (the buried Beer disappears for real).
- Future data wipes = edit the single truth directly (+ history erase per the deletion policy in CLAUDE.md).

## 3. Settings snapshots — kept, race-free

- Per-day snapshots `b/c/g/m` remain the rule (settings-of-the-day; closed days immutable).
- They are written onto the **open day** as part of every remote write that touches it (entry, weight, settings save). When the day passes it is already complete. No lazy stamping exists anywhere.

## 4. Settings save: no invented values

- An empty or invalid Settings field keeps its previous value. The app never substitutes a default on save.
- First-run seed defaults remain (visible in Settings, replaced by the first save).

## 6. Sync pill semantics

- `live` (green — remote confirmed) · `saving` · `offline` (read-only) · `error`. No "local" state exists anymore.

## 7. Implementation map

- Replace pull/push/scheduleSync with two functions: `fetchState()` (GET + sha) and `write(mutator)` (fetch → mutate → PUT sha, retry ≤ 3, then re-render).
- All mutations funnel through `write()`: addEntries, delEntry, saveWeight, food CRUD, saveSettings. Each is a small pure mutator so conflict-retry reapplication is trivially safe.
- Boot: render from cache → `fetchState()` → re-render. Inputs disabled in offline state.
- Secrets stay device-local as today. Demo mode stays fully local (stubbed remote), remains the test harness.
