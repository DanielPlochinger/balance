# Balance v2.5.2 — bottom-sheet overhaul

Status: SHIPPED 2026-08-16 — tag `v2.5.2`. Approved by Daniel at the localhost audit (first release through the full Dropbox-approval protocol).

Carried into this release (built during 2.5.1 audit, never pushed): grey vertically-centered day-sheet arrows, day-sheet 60% min-height, demo variety (item counts 2–15, zero-item gap day).

## 1 — One dismissal vocabulary

**Change — LOCKED 2026-08-16**

- Informational sheets → **Close**. Sheets with a pending action → **Cancel**. Destructive confirms → red verb + **Cancel**.
- "Keep" (delete-entry confirm) is replaced accordingly.

## 2 — Remove the grabber

**Change — LOCKED 2026-08-16**

- The drag-handle is removed from all sheets (it promises a drag that doesn't exist).
- Top padding adjusted so titles keep comfortable clearance.

## 3 — Dirty sheets ignore outside-tap

**Change — LOCKED 2026-08-16**

- Parse confirm, manual entry, and the food editor never dismiss on outside tap — Cancel is the explicit exit. No "discard changes?" layer.
- All other sheets keep outside-tap dismissal.
  *Intent: deterministic exemption by sheet, not dirtiness detection.*

## 4 — Height rules codified

**Change — LOCKED 2026-08-16**

- All sheets size to content with the existing 88dvh maximum.
- Exception, explicitly temporary: the day sheet keeps its 60% min-height so arrow-stepping doesn't resize the window. Revisit if it bothers Daniel.

## 5 — Pinned sheet footer

**Change — LOCKED 2026-08-16 (Daniel's go)**

- One footer construct defined in the sheet component: buttons pinned to the sheet's bottom edge; content scrolls beneath; solid sheet background (no glass/blur inside sheets).
- Footer button rules (Daniel, 2026-08-16): one shared height for all footer buttons — emphasis by fill only, never size. One button → full width; two → equal halves, **Cancel left, action right** (Apple HIG), primary filled, secondary plain.
- No separator at rest. A soft shadow (never a hairline) appears only while content is scrolled behind the footer — the iOS scroll-edge pattern — and disappears at the bottom of the scroll.
- Exactly one footer per sheet; three sanctioned layouts: [Primary + Cancel] · [Close] · [red verb + Cancel].
- All nine sheet uses adopt it; per-sheet inline button rows are removed.
- Food editor conformance: footer becomes [Save + Cancel]; Delete moves into the sheet content as a quiet red "Delete food" action, and gains the standard destructive confirm ([Delete red + Cancel]) — matching the entry-delete pattern. No sheet ever has three footer buttons.

## 6 — Remove aliases

**Change — LOCKED 2026-08-16**

- The alias concept goes entirely: editor field, list display, alias search matching, and the alias portion of the parser's library lines. (Never used — every stored alias list is empty; any stored `a` keys stay as inert data.)

## Rejected

- Background scroll-lock while a sheet is open — Daniel: bleed-through is fine for an overlay.
